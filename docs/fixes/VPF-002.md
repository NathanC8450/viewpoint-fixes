# VPF-002: furniture pick up / place / rotate

- **Status:** fixed (ours), verified in game with mouse/keyboard (crosshair and cursor mode); controller first pass, mostly working
- **Seen on:** Viewpoint 0.1.5a-hotfix, Project Zomboid 42.21
- **Code:** `Contents/mods/ViewpointFixes/common/media/lua/client/ViewpointFixes/fixes/VPF_002_MoveableCursor.lua` (uses `Adapter.lua`)

## Symptom
Choosing Pick up, Place or Rotate furniture (the move-furniture cursor) shows no usable outline, and nothing can be picked up, placed or rotated. It happens in first and third person.

## Cause
Verified by reading the game's flow and tracing calls:
1. The cursor is validated and drawn only from the game's isometric world render (`OnDoTileBuilding2` with `isRender=true`). Viewpoint replaces that render, so the validation never runs and `canBeBuild` is never set.
2. Clicks are read through the Attack binding and the raw left mouse button. Both read as permanently held under Viewpoint, so a click can never be detected.
3. The cursor's ghost sprite is drawn in isometric screen space. The game's iso-to-screen conversion is not 3D-aware under Viewpoint.
4. Viewpoint's interaction menu deliberately shows nothing while a placement cursor is out.

On a controller there is a further cause (verified from a log): the game's controller cursor position (`xJoypad`/`yJoypad`) is set up by the iso render path too, so it stays nil. The d-pad then raises Lua errors, and A finds the cursor never validated.

## What the fix does
- While the game's render calls are missing, the fix drives the cursor itself every frame: it picks the target tile from Viewpoint's aim, validates it with the game's own `isValid`, and runs the game's own `tryBuild` when the player accepts.
- Choices (objects to pick up, facings to rotate or place) are offered in Viewpoint's own interaction menu, so they are picked with Viewpoint's scroll and accept keys like any other interaction. Each facing is listed once, and the current one is greyed out.
- If Viewpoint shows no menu for the target, a line of helper text (optional, off by default) shows the current choice and Viewpoint's take key accepts it.
- Controller: the cursor follows the tile under the crosshair; the game's own button handling (mode, rotate, accept, cancel) then works as designed.
- The fix steps aside whenever the game's render calls are arriving, so it is inert in 2D view.

## If Viewpoint handled this itself
Run the cursor's validation and click handling from Viewpoint's own per-frame loop, with Viewpoint's aim as the picked tile, and draw a 3D outline or ghost. Our `Adapter` calls for the mouse point, crosshair point, interaction-menu wrap and accept key would not be needed.

## Check list
1. 3D view, crosshair mode: open the move-furniture mode, aim at a radio or mattress, pick it up, then place it, then rotate it. Each should go through Viewpoint's menu.
2. Same in cursor mode.
3. Rotate a mattress: each facing appears once, the current one is greyed.
4. Controller: radial menu, move furniture, aim the camera at furniture; A picks up / places / applies, LB changes mode, RB cycles, B cancels. No Lua errors from the d-pad.
5. 2D view: vanilla behaviour is unchanged.

## Retire when
Viewpoint validates and draws placement cursors itself, or fires `OnDoTileBuilding2` with `isRender=true` for them. The fix already stands down when it sees those render calls.

## Known issues
- No 3D preview of the furniture; the pad shows only the game's 2D ghost, which vanishes after X rotates in place mode.
- Controller: A on the facing the object already has ends with the character sitting on the ground (see `docs/backlog.md`).
- Rotating a table-top item on a faced table snaps back to the table's facing. That is vanilla design, not this bug.
